## 一、高 CPU 占用

### 症状
进程长期占据 100% 单核 CPU，持续数小时。

### 排查

```bash
# 1. 确认 CPU 热点
top -pid <PID>
# 或
ps aux | grep reasonix

# 2. 采样分析
sudo sample <PID> 5 -file /tmp/reasonix-sample.txt
```

### 常见原因

| 原因 | 判定方法 | 解决 |
|------|---------|------|
| **Goal 模式分析瘫痪** | 检查是否配置 `planner_model` + 目标模糊 | 清除 goal，用更具体的目标重试 |
| **Compaction 循环** | 检查 `compactStuck` 日志 | 手动 `/compact` 或 `/new` |
| **死循环工具调用** | 查看 transcript 中是否有重复调用模式 | 取消 turn |
| **MCP 服务器挂死** | `/mcp` 查看状态 | `/mcp connect <name>` 重连或禁用 |

## 二、Goal 模式异常

### 症状: AI 不断读文件但不写代码

**根因**: 双模型下 Planner 收到矛盾指令（系统提示让产出计划，Goal 块让执行下一步）

**判定**: 
1. 检查是否配置了 `planner_model`
2. 检查目标是否是"研究/了解/分析"类

**解决**:
- 使用更具体的目标（"添加 X 功能"而不是"研究 X"）
- 设置 `PlannerMaxSteps ≤ 15`
- 或暂时移除 `planner_model` 使用单模型

### 症状: Goal 提前停止（blocked）

**原因**:
- 50 turn 上限
- 连续 3 次相同 `[goal:blocked:<reason>]`
- 用户取消

**解决**: 清除后重新设定更窄的目标

## 三、MCP 连接问题

### 症状: `mcp__server__tool` 调用报错

```
MCP server "xxx" failed to start
MCP server "xxx" is still initializing
```

### 排查

```bash
# 1. 检查服务器配置
cat ~/.reasonix/reasonix.toml | grep -A10 '\[\[plugins\]\]'

# 2. 检查服务器状态
/mcp

# 3. stdio 服务器: 手动测试命令
npx -y @modelcontextprotocol/server-filesystem . --version

# 4. 查看 stderr
# 在 TOML 中添加 stderr 捕获路径
```

### 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| `command not found` | PATH 不包含 npx/node | 使用绝对路径或在 env 中设置 PATH |
| `still initializing` | lazy 层首次调用握手未完成 | 等下一 turn 再试 |
| `no tools exposed` | 服务器连接成功但无工具 | 检查服务器日志 |

## 四、前缀缓存问题

### 症状: token 消耗异常高

**判定**: 查看 StatusBar 中的 `cache-hit%`

| 值 | 状态 |
|----|------|
| > 80% | ✅ 正常 |
| 50-80% | ⚠️ 部分缓存命中 |
| < 50% | ❌ 缓存基本失效 |

### 常见原因

| 原因 | 解决 |
|------|------|
| 频繁 `/new` | 每个 session 重新构建 prefix |
| Compaction 后 | 压缩改变了 prefix → 下一次调用 cold start |
| Skill enable/disable | 重启 session 重建 prefix |
| `/model` 切换 | 切换模型重建 prefix |

**正常行为**: 每次 session 的前几次调用是 cold start（cache miss），之后逐渐收敛。

## 五、沙箱问题

### 症状: bash 工具执行被阻止

```
Operation not permitted (sandbox)
```

**原因**: macOS Seatbelt 限制写入范围

**解决**:
- 检查操作用到的路径是否在 `WriteRoots` 内
- 临时关闭: `[tools.bash] sandbox = "off"`
- 或关闭后重试
