# OMP vs DeepSeek-Reasonix 前缀缓存对比分析

## 核心发现

**OMP 的缓存基础设施与 Reasonix 本质等价。**

| 能力 | OMP | Reasonix |
|------|-----|----------|
| 前缀稳定性 | `appendOnlyContext`（已自动为 DeepSeek 启用） | 一次构建永不改变 |
| 消息只追加 | `AppendOnlyLog` | `session.Add()` |
| 前缀稳定性检测 | `computeFingerprint`（FNV hash） | `CaptureShape`（SHA256） |
| 工具数量 | 25+ | 15（Economy） |
| 工具描述裁剪 | `pruneToolDescriptions` / `inlineToolDescriptors` | N/A（工具更少） |
| reasoning_content round-trip | ✅ `requiresReasoningContentForAllAssistantTurns` | ✅ |
| 缓存命中率（理论） | **≈ 95%+**（prefix 稳定） | **≈ 95%+**（prefix 稳定） |

## 关键纠正

**工具数量不影响缓存命中率。** 缓存命中率只取决于前缀字节是否稳定——只要 `appendOnlyContext` 确保 system prompt + tools 冻结、消息只追加，DeepSeek 服务端就会自动缓存并命中，跟工具数量没关系。

OMP 的 `appendOnlyContext` 已经为 DeepSeek 自动启用（`settings-schema.ts`：`"Cache system prompt + tool specs and keep an append-only message log so provider prefix caches (DeepSeek, Xiaomi/SGLang, Anthropic) hit at maximum rate."`），所以**当前 OMP 在 DeepSeek 上的缓存命中率应该已经很高**。

## 工具数量减少的实际收益

既然不提高命中率，那减少工具干什么？

### 收益 1：冷启动成本

DeepSeek v4-flash 定价：
- 缓存命中：¥0.02/1M tokens
- 普通输入：¥1/1M tokens

| 场景 | 25 工具 (~3000 schema token) | 15 工具 (~1500 schema token) |
|------|------|------|
| 冷启动（第一轮 + cache 过期） | ¥0.003 + ¥0.0015（schema）= ¥0.0045 | ¥0.0015 + ¥0.0015（schema）= ¥0.003 |
| **每冷启动节省** | — | **¥0.0015 / 次** |

**冷启动只占全部 token 的很小一部分**，实际收益不大。

### 收益 2：DeepSeek v4-flash 模型质量

**这是更大的收益**。v4-flash 是入门级模型，能力有限。25+ 工具的 schema 占用大量 context（约 3000-5000 token），模型需要在工具选择上消耗额外注意力。

Reasonix 选择 Token Economy 的核心原因之一也是质量——对弱模型来说，工具越多越容易选错工具。15 个核心工具减少决策干扰。

### 收益 3：工具 schema 的 intent 字段

OMP 的 `intentTracing` 特性会在每个工具的 schema 中注入 `i`（intent）字段。如果 intent 内容在不对轮次间变化，**会导致 tool schema 字节改变 → 缓存前缀改变 → cache miss**。

`computeFingerprint` 的检查项包括 `intentTracing` 开关，但**不包括 intent 字段的内容**。这意味着如果 `i` 的提示文本跨轮变化，`StablePrefix` 不会 rebuild（fingerprint 未变），但实际的 tool schema 字节变了 → **DeepSeek 侧缓存 miss**。

这是**比工具数量更大的缓存问题**。需要验证。

## 结论

| 优化项 | 是否提高命中率 | 是否节约 token | 是否提升质量 |
|--------|--------------|---------------|------------|
| 减少工具数量 | ❌ | 微小（冷启动） | ✅（v4-flash） |
| 裁剪工具描述 | ❌ | 微小 | 无影响 |
| **稳定 intent 字段** | ✅ 可能 | ✅ | 无影响 |
| appendOnlyContext | ✅ 核心 | ✅ 核心 | 无影响 |
