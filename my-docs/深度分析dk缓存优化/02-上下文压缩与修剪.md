# 二、上下文压缩与修剪

当对话上下文接近模型上下文窗口上限时，通过压缩和修剪来释放空间，避免请求被截断。这些机制是通用设计，不依赖特定模型。

## 1. 自动压缩触发 (Auto-Compact)

**文件：** `internal/agent/compact.go:84-135` — `maybeCompact()`

**触发条件：** 每次 tool loop 结束后检查。当最新一轮的 `PromptTokens` 超过 `compactRatio × contextWindow` 时触发自动压缩。

```
阈值策略：
  50% (softCompactRatio)  → 发出一次性通知，不压缩（保留缓存前缀）
  80% (compactRatio)      → 触发压缩（默认）
  90% (compactForceRatio) → 强制压缩，即使经济性评估不划算
```

**流程：**
1. **修剪**（不调用 API）— 删除旧工具结果中的大段输出，替换为 `[elided tool result — <name>, <N> bytes dropped]`
2. **分区** — 将消息历史分为三段：**固定开头**（保留前几条 user turns）+ **可折叠区域**（中间部分）+ **最近尾部**（最后 N 条消息）
3. **经济性评估** — 如果折叠后节约 < 400 token，跳过（除非 force=true）
4. **总结** — 用 LLM 总结可折叠区域的内容
5. **替换** — 用总结替换中间部分

### 压缩后消息结构

```
Messages[0]:  system prompt                          ← 不变
Messages[1]:  固定的开头 user turn                     ← 保留
Messages[2]:  <compaction-summary>...总结内容...</compaction-summary>  ← 替换
Messages[3]:  最近的尾部消息                            ← 保留
```

**代价：压缩会破坏前缀缓存**（cache_shape.go:75-77 中的 `"log_rewrite"` 原因），因为消息数组被重写了。

## 2. 手动压缩

**文件：** `internal/control/controller.go:1056-1067`

用户输入 `/compact` 或 `/compact <focus>` 触发手动压缩，跳过经济性评估，总是执行。

## 3. 旧工具结果修剪

**文件：** `internal/agent/prune.go:29-82` — `PruneStaleToolResults()`

在压缩之前，先对可折叠区域中的**旧工具输出**进行修剪。将大段工具结果替换为简短标记：

```
[elided tool result — bash, 14580 bytes dropped]
```

这是"免费的"——不需要调用 API，且数据是可重新获取的。只处理不在最近尾部中的旧工具结果，保留错误信息。

## 4. 工具输出截断

**文件：** `internal/agent/agent.go:1899-1914`

当单个工具输出超过 `maxToolOutputBytes`（32KB）时，截断为：
- 保留前 16KB
- 保留后 16KB
- 中间替换为 `[truncated N bytes]`

## 5. 文件引用截断

**文件：** `internal/control/refs.go:22`

`@` 引用的文件内容上限 64KB，超出部分截断并添加标记。
