## 一句话总结

**Reasonix 节约 token 的核心策略是：让 DeepSeek 的自动前缀缓存尽可能命中。**

具体来说：
1. **系统提示词永不改变** — 一个 session 内 system message 只构建一次，后续每次请求都相同
2. **工具定义永不改变** — tool schemas 注册后不变
3. **新内容只追加在末尾** — 不修改已有的消息数组，只 append 新的 user/assistant/tool 消息
4. **当上下文超限时，压缩中间部分** — 用 LLM 总结旧内容，替换为更短的版本，然后继续追加

这四条原则使得请求的前 N 个 token 在每轮对话中完全一致，DeepSeek 服务端自动缓存这部分前缀，后续请求只对新增的尾部 token 计费。

## 关键发现

- **DeepSeek 没有特殊的缓存参数** — 前缀缓存是自动的，唯一要求是请求前缀的字节级一致性
- **99% 以上的命中率是可行的** — 只要遵守 cache-stable prefix 原则
- **压缩是双刃剑** — 压缩能释放上下文空间，但会破坏前缀缓存（因为重写了消息历史）
- **几乎所有优化都是通用的** — 不依赖 DeepSeek 专属参数，只是利用了其自动缓存特性
