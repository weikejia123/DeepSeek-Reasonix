# 一、自动前缀缓存（最核心的优化）

## 原理

DeepSeek API 的服务端会自动缓存请求消息数组的前缀部分。当连续请求的起始段字节完全一致时，第二次及后续请求的这部分 token **不计费**，只对新增的尾部 token 按正常价格收费。

这个缓存是**自动的、透明的**——不需要在请求中设置任何特殊的 header 或参数。

## 唯一要求

**请求消息数组的前 N 条消息的字节级一致性。**

具体到 Reasonix 的实现：

```
POST /chat/completions
{
  "model": "deepseek-v4-flash",
  "messages": [
    {"role": "system", "content": "You are Reasonix..."},   ← 永不改变
    {"role": "user",   "content": "第一轮的问题"},             ← 追加
    {"role": "assistant", "content": "第一轮的回复"},           ← 追加
    {"role": "user",   "content": "第二轮的问题"}              ← 追加
  ],
  "tools": [...]                                              ← 永不改变
}
```

- `messages[0]`（system）**永不改变**
- `tools` 数组 **永不改变**
- 每轮对话的消息只 **append**，**不修改**已有消息
- 结果：每轮请求的前 X 个 token 都命中缓存，只有最后一个 user message + 新增加的 assistant/tool 消息产生 cache miss

## 代码实现

### 1. 系统提示词只构建一次

**文件：** `internal/boot/boot.go:204-245`

`Build()` 函数在 agent session 启动时构建完整的 system message，包含以下部分（按顺序）：

```
1. 基础 system prompt      ← cfg.ResolveSystemPromptForRoot(root)
2. 输出风格 (outputstyle)  ← outputstyle.Resolve + Apply
3. 语言策略                ← "Reply in the same language..."
4. Token Economy 标记      ← "Token economy mode is on..."
5. 内存块 (REASONIX.md)    ← memory.Load() + memory.Compose()
6. 技能索引                ← skill.ApplyIndex()
```

这个 system message 在 session 的整个生命周期内**永不改变**。

### 2. 工具定义只注册一次

**文件：** `internal/boot/boot.go:247-263`、`internal/provider/provider.go:1155-1158`

工具 schema 注册在 `tool.Registry` 中，每次 API 请求时通过 `a.tools.Schemas()` 获取。同一个 session 内工具列表不变。

### 3. 新内容只追加在末尾

**文件：** `internal/agent/agent.go:690-691`

```go
a.session.Add(provider.Message{
    Role:    provider.RoleUser,
    Content: input,
})
```

`session.Add()` 只是 append，不修改已有消息。

### 4. 前处理不修改系统提示词

**文件：** `internal/control/input.go:91-133` — `Compose()` 函数

`Compose()` 在**用户输入**上做前处理（添加 goal 标记、plan 标记、reasoning language 等），而不是修改 system message。这些前处理最终作为 user message 的一部分发送，不影响 prefix 缓存。

### 5. 缓存命中率检测

**文件：** `internal/provider/openai/openai.go:503-524`

```go
func normaliseUsage(wire wireUsage) provider.Usage {
    // DeepSeek 返回的缓存数据在顶层字段
    // Azure/OpenAI 返回的缓存数据在嵌套字段
}
```

**文件：** `internal/provider/provider.go:331-339`

```go
type Usage struct {
    CacheHitTokens    int
    CacheMissTokens   int
    // ...
}
```

**文件：** `internal/agent/agent.go:1220-1221`

每次 API 返回后，累计 `CacheHitTokens` 和 `CacheMissTokens`。

### 6. 前缀变更检测

**文件：** `internal/agent/cache_shape.go:36-77`

```go
func CaptureShape() PrefixShape    // 捕获当前 prefix 的哈希
func CompareShape() CacheDiagnostics // 对比前后两次的 prefix 变化
```

当检测到 prefix 变化时（如压缩触发了 log rewrite），上报 `PrefixChanged: true` 和变更原因。

## 缓存定价

从 `internal/config/config.go:1193-1197`：

| 模型 | 缓存命中 (per 1M tokens) | 普通输入 (per 1M tokens) |
|------|------------------------|------------------------|
| deepseek-v4-flash | ¥0.02 | ¥1 |
| deepseek-v4-pro | ¥0.025 | ¥3 |

缓存命中时的价格为普通输入的 **1/50 ~ 1/120**。一个 session 如果维持 95%+ 的命中率，输入 token 成本可以降低 95% 以上。
