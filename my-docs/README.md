# my-docs — 目录规范

## 编号区间

| 区间 | 目录 | 回答的问题 |
|------|------|-----------|
| 00-09 | `00-project-meta/` | 「这个项目是什么」— 仓库地址、端口号、作者信息等元信息 |
| 05-09 | `05-overview/` | 「这是什么」— L1 快速上手、核心概念、项目结构 |
| 05-09 | `06-architecture/` | 「数据怎么流」— L2 系统架构图、数据流、组件交互 |
| 05-09 | `07-extension-guide/` | 「怎么扩展」— L4 新增Tool/Skill/MCP/Provider/Hook/Command指南 |
| 10-19 | `01-dev-read/` | 「代码怎么写的」— L3 源码阅读分析、架构报告、模块解读 |
| 20-29 | `02-dev-faq/` | 「为什么 / 怎么用」— 二开问题解答、诊断记录 |
| 30-39 | `03-feature-action/` | 「正在做什么」— 功能设计草案、实施实录、bug 跟踪 |
| 40-49 | `04-capabilities/` | 「现在能做什么」— 当前代码已具备的基础能力清单 |
| 50+ | 预留 | |

## 规则

1. **区间间可跳号**，不用 `01/02/03/04` 紧贴——例如可以直接从 `01-dev-read` 跳到 `15-architecture`，不影响阅读流
2. **区间内序号不强制递增**——`05`、`12`、`28` 都可以，只要保持区间一致
3. **阅读顺序 = 序号升序 × 区间升序**——新人从 00 往上看就是合理的学习路径
4. **`my-docs/` 根目录保留 `README.md`、`INDEX.md` 和 `BRANCHES.md`**，其他全部入子目录。`BRANCHES.md` 是团队内部分支清单的速查卡，完整文档在 `00-project-meta/分支管理说明.md`
5. **能力文档面向二开者**——`04-capabilities/` 记录的是"当前代码已具备的、可被其他功能复用的基础能力"，不是用户文档
